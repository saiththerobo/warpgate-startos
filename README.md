# Warpgate on StartOS

> **Upstream repo:** <https://github.com/warp-tech/warpgate>

[Warpgate](https://warpgate.null.page/) is a smart SSH, HTTP, and database bastion host that works with any standard SSH client. Use it to securely proxy and record access to your servers and services, with a modern web admin interface and per-user access control.

## Volume and Data Layout

| Volume | Mount Point | Purpose                                                     |
| ------ | ----------- | ----------------------------------------------------------- |
| `main` | `/data`     | SQLite database, SSH host keys, recordings, generated config |

### Files written at startup

| Path                   | Written by | Purpose                                 |
| ---------------------- | ---------- | --------------------------------------- |
| `/data/warpgate.yaml`  | `main.ts`  | Generated server config (ports, paths)  |
| `/data/db`             | Warpgate   | SQLite database (users, targets, roles) |
| `/data/ssh-keys/`      | Warpgate   | SSH host keys (auto-generated)          |

## Installation and First-Run Flow

1. Install the package — StartOS shows a **critical task**: *Create your admin account via the web interface*.
2. Open the Warpgate web interface. You are automatically redirected to the first-time setup wizard.
3. Create your admin username and password in the wizard.
4. Dismiss the critical task once setup is complete.

## Configuration Management

`warpgate.yaml` is generated by `main.ts` on every startup and written to the volume. It is not user-editable — all meaningful runtime configuration (targets, users, roles, policies) is managed through the Warpgate web UI and stored in the SQLite database.

**Generated config:**

```yaml
database_url: "sqlite:/data/db"
http:
  listen: "0.0.0.0:8888"
  trust_x_forwarded_headers: true
mysql:
  enable: false
  listen: "0.0.0.0:33306"
ssh:
  listen: "0.0.0.0:2222"
  keys: "/data/ssh-keys"
  host_key_verification: prompt
recordings:
  enable: false
  path: "/data/recordings"
```

`trust_x_forwarded_headers: true` is required for the StartOS reverse proxy to pass real client IPs.

## Network Access and Interfaces

| Interface   | Port | Protocol | Purpose                                   |
| ----------- | ---- | -------- | ----------------------------------------- |
| Web UI      | 8888 | HTTP     | Admin interface — manage targets and users |
| SSH Gateway | 2222 | TCP      | SSH client connections through the bastion |

**Connecting via SSH:**

```
ssh user@target@<warpgate-host> -p 2222
```

The username format is `<warpgate-username>@<target-name>`.

## Backups and Restore

**Included in backup:**

- `main` volume (SQLite database, SSH host keys, generated config)

**Restore behavior:** Volume is fully restored before the service starts. All users, targets, and roles are preserved. No post-restore action is needed.

## Limitations and Differences

1. **HTTP mode** — Warpgate serves plain HTTP internally; StartOS adds TLS at the proxy layer. The upstream default is self-signed HTTPS; this package disables that to integrate with StartOS's certificate management.
2. **Recordings disabled** — Session recording is disabled by default to reduce storage usage. Enable it via the Warpgate admin UI (note: recordings are stored in the backup volume).
3. **MySQL proxy disabled** — The MySQL proxy is disabled in the generated config. SSH and HTTP proxying work out of the box.

---

## What Is Unchanged from Upstream

The Warpgate binary runs unmodified. All user data (targets, credentials, sessions) is managed entirely through Warpgate's own web UI and stored in its SQLite database.

## Quick Reference for AI Consumers

```yaml
package_id: warpgate
```
